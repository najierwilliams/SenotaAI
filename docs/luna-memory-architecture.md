# Luna Memory Architecture

## Scope

Luna memory is a durable, owner-scoped working layer connected to—but distinct from—the released Knowledge Space object graph. It stores concise context required for planning and follow-up work without copying the full workspace into a model prompt. The design preserves provenance, truth state, version history, and reversibility for Luna-owned routine changes.

| Memory dimension | Stored representation | Constraint |
|---|---|---|
| Kind | `WORKING`, `EPISODIC`, `SEMANTIC`, `PROCEDURAL`, `PROJECT`, `RESEARCH`, `SELF` | Kind explains intended use; it is not an evidence-quality claim. |
| Truth state | `INFERENCE`, `HYPOTHESIS`, `ASSUMPTION`, `UNKNOWN`, `PROPOSED`, `CONTRADICTED`, `UNMAPPED`, `NOT_ESTABLISHED`, `UNAVAILABLE`, or `PROVIDER_UNAVAILABLE` | Luna automation cannot create factual, evidentiary, validated, or provider-confirmed truth. |
| Source | `USER`, `LUNA`, `SYSTEM`, `PROVIDER`, or `PUBLISHED` | Source is explicit and is retained independently from model confidence. |
| Provenance | Source-object identifiers, tags, structured provenance, optional project/mission linkage | A memory does not replace a cited source object. |
| Lifecycle | Active, archived, versioned, and optionally rolled back | Only Luna/system-owned memory is eligible for rollback through the cognitive control. |

## Ownership and immutability

All memory queries include the verified owner’s Knowledge Space workspace identifier. The browser receives no direct database access. The repository rejects Luna automation that attempts to create an elevated scientific truth state. It also rejects automated changes to `PROVIDER` or `PUBLISHED` memory, retaining such records as source evidence rather than editable working notes.

> **Principle:** An inferred memory can describe a gap, contradiction, task, or next step. It cannot become a scientific fact merely because it is repeated, highly ranked, or generated by a model.

Provider snapshots in the underlying Knowledge Space retain their existing immutable protection. When a worker needs to record a synthesis, it creates a separately marked inferred note and cites the source-object identifiers rather than changing a source record.

## Retrieval and prompt construction

Retrieval ranks relevant persisted memory while retaining source and truth labels. The worker executor also requests at most eight matching Knowledge Space objects through the named, owner-scoped controlled tool. The combined context is character-bounded before any model call. This prevents hidden full-workspace injection and keeps model output tied to inspectable persisted material.

| Stage | Bound | Outcome |
|---|---|---|
| Query normalization | Short, non-empty task/objective query | Avoids unbounded text or arbitrary query syntax. |
| Cognitive-memory retrieval | Bounded result set | Prioritizes relevant classified memory. |
| Knowledge Space retrieval | At most eight matching objects | Retrieves current owner-scoped source context without duplication. |
| Prompt assembly | 18,000 characters for worker execution | Includes provenance/truth context, scientific boundaries, and no hidden history. |
| Report persistence | 18,000 characters maximum | Creates an inferred software-worker handoff note, never provider evidence. |

## Consolidation and rollback

Duplicate consolidation compares only exact normalized content. It selects a canonical record, archives only eligible Luna-owned duplicates, and writes an explicit `CONSOLIDATES` memory link. Near matches are retained because semantic similarity is not sufficient evidence to delete or merge a distinct working record.

Every self-state, memory, project, goal, task, mission, and worker change retains a version snapshot and audit event. A memory rollback reads a requested prior snapshot, creates a later version rather than overwriting history, and records the owner’s reason. It never rolls back provider or published evidence.

## Evidence boundaries retained in memory

Memory retrieval and software-worker prompts preserve the released spatial and ontology conclusions: the checksum-bound HRA Brain-Female v1.1 visual GLB has no established transform to MNI ICBM 152 2009c; HRA-to-Julich mapping remains unavailable; and the retained Julich result is 0 authoritative / 0 probabilistic / 0 requires-domain-review / 102 unmapped. These are evidence boundaries, not requests for a model to estimate missing coordinates.

Luna memory also makes the software/physical distinction explicit. A worker handoff is a software record. It is never a nanotechnology claim, a biological target, a medical conclusion, or an instruction for tissue, cell, molecular, or subcellular manipulation.
